# 09 · 多模态基础

> 核心考点：CLIP 对比学习、ViT、图文对齐、多模态大模型架构、幻觉评估

---

### Q1 【基础】CLIP 的核心思想是什么？对比学习怎么做的？

- **答案要点**：
  1. 核心思想：从海量图文对中学习，让匹配的图文对在向量空间中靠近，不匹配的远离。
  2. 架构：图像编码器（ViT/ResNet）+ 文本编码器（Transformer），各自把图像和文本映射到同一个 embedding 空间。
  3. 对比学习损失：一个 batch 里有 N 个图文对，计算 N×N 的图文相似度矩阵；对角线是正样本（匹配的），非对角线是负样本；用 InfoNCE 损失——拉近对角线，推远非对角线。
  4. 效果：CLIP 学到的是通用视觉概念表示，可以做 zero-shot 分类——把类别名写成文本，和图片算相似度就行。
- **追问点**：
  - CLIP 为什么需要那么多数据？（答：对比学习需要海量负样本才能学到好的表示；CLIP 用了 4 亿图文对）
  - CLIP 的局限？（答：对细粒度分类、计数、空间关系不擅长；zero-shot 能力有限）

---

### Q2 【基础】ViT 和 CNN 的区别？ViT 为什么需要大数据预训练？

- **答案要点**：
  1. CNN：卷积操作，局部感受野，层叠扩大感受野；有归纳偏置（平移不变性、局部性）。
  2. ViT（Vision Transformer）：把图片切成 patch（如 16×16），每个 patch 当作一个 token，直接喂 Transformer；没有卷积，全局注意力。
  3. 为什么需要大数据：ViT 没有 CNN 那样的归纳偏置（局部性、平移不变），一切都要从数据中学；小数据集上 ViT 不如 CNN，大数据预训练后 ViT 反超。
  4. 大数据预训练：在 JFT-300M 等超大数据集上预训练，然后迁移到下游任务。
- **追问点**：
  - ViT 的 patch 大小怎么选？（答：常用 16×16 或 32×32；patch 越小，序列越长，计算越贵但细节越好；16×16 是比较平衡的选择）

### Q3 【进阶】图文对齐（Image-Text Alignment）为什么难？

- **答案要点**：
  1. 模态差异：图像是连续的像素信号，文本是离散的符号；二者的语义空间完全不同，要对齐到同一个向量空间。
  2. 粒度差异：一张图有无数细节，一句描述只提了几个重点；什么该对齐、什么不该对齐，很难学。
  3. 多义性：同一张图可以有多种描述方式；同一句话可以对应很多图。
  4. 数据噪声：网络图文对的 caption 经常不精确、不完整；对比学习的负样本也可能是"假负例"（其实匹配但被当成不匹配）。
- **追问点**：
  - 为什么多模态模型经常"看不见"小物体？（答：因为预训练的图文对中，小物体很少被 caption 提到；模型没有学到小物体和文本的对应关系）

---

### Q4 【进阶】多模态大模型（如 GPT-4V）的架构一般是什么样的？

- **答案要点**：
  1. 主流架构（LLaVA 范式）：
     - (a) 图像编码器：预训练好的 CLIP ViT，把图片编码成视觉特征序列。
     - (b) 对齐层（投影层）：把视觉特征映射到 LLM 的 embedding 维度（如 MLP 或线性层）。
     - (c) LLM：接一个预训练好的大语言模型，视觉 token 和文本 token 拼在一起输入。
  2. 训练流程：(a) 第一阶段：只训练对齐层，让视觉特征和 LLM 词空间对齐；(b) 第二阶段：指令微调，用图文指令数据训练模型学会回答问题。
  3. 为什么不端到端从头训？（答：太贵；复用预训练好的视觉编码器和 LLM，只训练中间对齐层，成本低效果好）
- **追问点**：
  - 为什么图像 token 数很多？（答：一张 224×224 的图，patch=14，就是 16×16=256 个视觉 token；比一句话的 token 多很多，占上下文空间）

### Q5 【实战】多模态模型怎么做幻觉评估？

- **答案要点**：
  1. 事实性幻觉：描述了图里没有的东西。
  2. 评估方法：(a) 人工评估（金标准）；(b) 用更强的多模态模型做 judge；(c) 构造有标准答案的测试集（如"图里有几个红方块"）。
  3. 常见幻觉类型：(a) 编细节——图里模糊的地方模型脑补；(b) 数量错——数错物体个数；(c) 属性错——颜色、大小搞错。
  4. 缓解：和文本模型类似——更好的训练数据、RLHF、让模型先描述再回答。
- **追问点**：
  - 多模态幻觉比文本幻觉更严重吗？（答：是的，因为视觉理解本身就难，模型经常"看不懂但自信地编"；尤其是细粒度细节）

### Q6 【进阶】为什么多模态模型经常"看不见"图里的小物体？

- **答案要点**：
  1. 分辨率问题：图片经过 patch 化后，小物体可能只占 1~2 个 patch，信息被压缩了。
  2. 训练数据问题：网络图文对中，caption 一般只描述大物体和主要内容，小物体很少被提到；对比学习学不到小物体的语义。
  3. 注意力分散：视觉 token 很多，模型注意力都放在主要物体上，小物体的信号被淹没。
  4. 缓解：高分辨率输入、动态分辨率、专门的细粒度数据集微调。
- **追问点**：
  - GPT-4V 是怎么解决这个问题的？（答：据传用了高分辨率 + 多 cropped 图拼接的方式，把图片切成多个高分辨率块分别处理再融合）

### Q7 【实战】做一个图文问答系统，你会怎么选架构？

- **答案要点**：
  1. 需求明确：是通用问答还是特定领域？精度要求高不高？延迟要求？
  2. 方案选择：
     - (a) 预算少、快速上线：直接调 GPT-4V / Claude 3 等 API。
     - (b) 私有化部署、中等预算：LLaVA / Qwen-VL 开源模型 + 微调。
     - (c) 特定领域、高精度：在开源多模态模型上用领域数据微调。
  3. 架构：图像编码器 + 对齐层 + LLM（LLaVA 范式）；如果需要 OCR，加专门的 OCR 模块。
- **追问点**：
  - 表格图片怎么处理？（答：专门的表格理解模型，或者先 OCR 出文本再用 LLM 处理）

### Q8 【进阶】LLaVA 的架构是什么？简单描述一下。

- **答案要点**：
  1. 视觉编码器：CLIP ViT-L/14，冻结，提取图像特征。
  2. 对齐层：一个 MLP（两层），把视觉特征投影到 LLM 的 embedding 维度。
  3. LLM：Vicuna（基于 LLaMA 的指令微调模型）。
  4. 训练两阶段：
     - 第一阶段：只训练对齐层，用图文对做"图像特征→文本"的对齐；MLP 把视觉特征映射到 LLM 词空间。
     - 第二阶段：指令微调，用图文指令数据训练整个模型（视觉编码器冻结，对齐层+LLM 可调）。
  5. 为什么重要：LLaVA 证明了"冻结 CLIP + 冻结 LLM + 一个简单对齐层"就能做出不错的多模态模型，大幅降低了多模态研究门槛。
- **追问点**：
  - LLaVA 的局限？（答：分辨率低、小物体看不见、幻觉多；后续版本 LLaVA-1.5/1.6 改进了这些）

### Q9 【实战】多模态模型的推理瓶颈在哪里？

- **答案要点**：
  1. 视觉编码器：图像特征提取是计算密集型，大图/高分辨率很贵。
  2. 视觉 token 太多：一张图几百个视觉 token，占大量上下文，KV Cache 膨胀。
  3. 架构复杂：比纯文本模型多了视觉编码器部分，部署更复杂。
  4. 优化方向：高分辨率下用动态分辨率、视觉 token 压缩（把多个 patch 合并）、视觉编码器量化。
- **追问点**：
  - 视觉 token 压缩是什么？（答：把 256 个视觉 token 压缩到 64 个，减少上下文占用；代价是细节损失）

### Q10 【进阶】CLIP 之后有哪些重要的多模态预训练工作？

- **答案要点**：
  1. ALIGN：Google，用更粗糙的 alt-text 数据和更大的 batch 做对比学习。
  2. BLIP：Salesforce，引入文本编码器生成的 synthetic caption 做数据增强。
  3. Flamingo：DeepMind，在冻结的 LM 上加 perceiver resampler 接视觉特征，做少样本多模态。
  4. Llava/Qwen-VL/InternVL：把视觉接到 LLM 上做通用多模态对话。
  5. 趋势：从"图文检索/分类"走向"通用多模态对话"；视觉和语言越来越深度融合。
- **追问点**：
  - 现在最强的开源多模态模型有哪些？（答：Qwen-VL-Max、InternVL 系列、LLaVA-NeXT、GPT-4o 是闭源标杆）
