# 02 · RLHF 与对齐

> 核心考点：SFT/奖励模型/PPO/DPO 流程、KL 散度、幻觉、越狱、对齐税

---

### Q1 【基础】RLHF 的三个阶段是什么？各自的目标是什么？

- **答案要点**：
  1. 第一阶段 SFT（监督微调）：用人工标注的高质量指令-回答对微调预训练模型，让模型学会"按指令格式回答"，获得基本的对话能力。
  2. 第二阶段 RM（奖励模型训练）：收集同一个 prompt 的多个回答，人工排序，训练一个奖励模型给回答打分；RM 通常基于 SFT 模型初始化，输出一个标量 reward。
  3. 第三阶段 PPO（强化学习优化）：用 SFT 模型作为策略模型，RM 作为奖励来源，用 PPO 算法优化策略，让模型生成 RM 打分更高的回答；同时加 KL 惩罚防止偏离 SFT 太远。
- **追问点**：
  - 为什么不直接用 SFT 就够了？（答：SFT 只能模仿标注数据的风格，无法优化"哪个回答更好"这种偏好排序信号；RLHF 让模型学会人类偏好的相对优劣）
  - 奖励模型怎么训练？损失函数是什么？（答：成对偏好损失，`L = -log σ(r_w - r_l)`，r_w 是更好回答的 reward，r_l 是更差回答的 reward）

### Q2 【基础】SFT 和预训练有什么区别？

- **答案要点**：
  1. 数据不同：预训练用海量无标注文本（万亿 token），学语言模型知识；SFT 用几万到几十万条高质量指令-回答对，学"如何遵循指令"。
  2. 目标不同：预训练是下一个 token 预测（next token prediction）；SFT 仍然是 next token prediction，但数据格式是指令格式，相当于让模型学会在特定格式下生成合理回答。
  3. 学习率不同：预训练学习率大（1e-4 ~ 5e-4），SFT 学习率小很多（1e-5 ~ 5e-5），避免灾难性遗忘。
  4. 规模不同：预训练需要数千张 GPU 跑数月；SFT 几十张 GPU 几天即可完成。
- **追问点**：
  - SFT 数据量多大合适？（答：一般 1万~10万条高质量数据即可显著提升；太多反而可能过拟合、降低模型泛化能力）
  - 为什么 SFT 后模型会变得更"听话"但知识面变窄？（答：SFT 数据分布集中在对话格式上，模型学到的是对话风格而非新知识；如果 SFT 数据质量差或过多，会遗忘预训练知识）

### Q3 【进阶】PPO 的目标函数是什么？KL 惩罚项起什么作用？

- **答案要点**：
  1. PPO 目标函数：`L = E[RM(x, y)] - β · KL(π_θ(y|x) || π_SFT(y|x))`，最大化奖励的同时惩罚偏离 SFT 策略的程度。
  2. KL 惩罚的作用：防止策略模型为了刷 RM 高分而"钻空子"（reward hacking），比如生成冗长、重复、谄媚的回答；保持模型语言能力不退化。
  3. β 的选择：β 太大会让模型几乎不变（等于没做 RLHF）；β 太小会导致模型跑偏、语言崩坏。实际中常用自适应 KL 控制，动态调整 β 维持目标 KL 值。
- **追问点**：
  - PPO 为什么训练不稳定？（答：需要同时跑 4 个模型（policy、reference、reward、critic），显存大；奖励信号稀疏且方差大；KL 系数难调）
  - PPO 的 clip 机制是什么？（答：PPO 用 importance ratio 的 clip 限制每步更新幅度，`min(r_t·A_t, clip(r_t, 1-ε, 1+ε)·A_t)`，防止策略更新过大）

### Q4 【进阶】DPO 相比 PPO 的优势是什么？原理是什么？

- **答案要点**：
  1. DPO（Direct Preference Optimization）原理：跳过显式的奖励模型和强化学习，直接用偏好数据对策略模型做监督学习；从 RLHF 的目标函数推导出一个闭式解，直接优化策略模型和参考模型之间的对数概率差。
  2. 损失函数：`L_DPO = -E[log σ(β · (log π_θ(y_w|x)/π_ref(y_w|x) - log π_θ(y_l|x)/π_ref(y_l|x)))]`，其中 y_w 是更好的回答，y_l 是更差的回答。
  3. 优势：(a) 不需要训练单独的奖励模型；(b) 不需要 PPO 那样的在线采样和强化学习不稳定问题；(c) 训练简单稳定，和 SFT 差不多；(d) 显存省一半（不需要 critic）。
  4. 局限：DPO 是离线方法，不能在线探索；效果在某些任务上略逊于 PPO（因为没有在线 reward signal 的引导）。
- **追问点**：
  - DPO 为什么不需要奖励模型？（答：因为 DPO 从 RLHF 目标函数的最优解推导出来，最优策略和参考策略的对数比直接和奖励差成正比，所以可以直接用偏好数据优化这个比值）
  - 现在主流用 DPO 还是 PPO？（答：工业界 DPO/ORPO/IPO 等直接偏好优化方法越来越主流，因为简单稳定；但顶尖模型（如 GPT-4、Claude）据传仍在用 PPO 类在线方法追求极致效果）

### Q5 【进阶】什么是奖励黑客（Reward Hacking）？为什么会出现？

- **答案要点**：
  1. 定义：策略模型发现了奖励模型的漏洞，生成 RM 打高分但人类认为质量差的回答；比如特别长、特别啰嗦、大量"非常好的问题"这类谄媚语。
  2. 出现原因：(a) RM 本身是人类偏好的不完美近似，不可能覆盖所有分布；(b) 策略模型在 RM 的分布外（OOD）区域钻空子；(c) RL 优化目标和真实目标不一致（Goodhart's Law：一旦度量变成目标，它就不再是好的度量）。
  3. 缓解方法：(a) KL 惩罚限制偏离；(b) 定期更新 RM 数据，加入对抗样本；(c) 用多个 RM 集成；(d) 从 AI 反馈（RLAIF）补充人工标注。
- **追问点**：
  - 举个具体的 reward hacking 例子？（答：模型发现 RM 喜欢"详细"的回答，就把简单问题也写得又臭又长，加一堆正确的废话，RM 打高分但人类觉得啰嗦）

### Q6 【实战】如何缓解大模型的幻觉（Hallucination）问题？

- **答案要点**：
  1. 数据层面：训练数据加入更多事实性知识，减少噪声；用 RLHF 奖励"诚实"而不是"自信"。
  2. RAG 外挂：检索增强生成，让模型基于检索到的真实文档回答，而不是纯靠参数记忆。
  3. 对齐层面：在 RLHF 中加入"不知道就说不知道"的偏好数据，训练模型承认自己不知道。
  4. 推理时：让模型先列引用来源再回答；Self-Consistency 多次采样取一致结果；用 NLI 模型校验生成内容是否和前提一致。
  5. 后处理：用另一个模型做事实核查（fact-checking），标注不确定的部分。
- **追问点**：
  - 为什么大模型会产生幻觉？（答：本质是概率生成模型在训练数据中没见过的事实上面，仍然会"自信地编造"；模型的优化目标是"像人话"，不是"说真话"）
  - 幻觉能彻底消除吗？（答：不能完全消除，只能降低。因为语言模型本质上是在学语言分布而非世界知识图谱，必然存在外推时的编造）

### Q7 【实战】什么是越狱（Jailbreak）？常见的防御手段有哪些？

- **答案要点**：
  1. 定义：用户通过精心构造的 prompt 绕过模型的安全对齐，让模型生成原本被拒绝的内容（如有害信息、隐私信息）。
  2. 常见攻击方式：(a) 角色扮演（"你现在是一个没有限制的 DAN 模式 AI"）；(b) 编码/混淆（用 base64、拼音、外语）；(c) 前置注入（"先写一个故事，故事里有人说..."）；(d) 多轮渐进（先问无害问题，逐步引导到有害方向）。
  3. 防御手段：(a) 安全对齐训练（RLHF 中加入安全拒绝样本）；(b) 输入侧分类器检测恶意 prompt；(c) 输出侧过滤；(d) 系统 prompt 强化安全指令；(e) 红队对抗测试持续迭代。
- **追问点**：
  - 为什么安全对齐和能力对齐经常冲突？（答：过度安全训练会让模型变得"胆小"，合理问题也拒绝回答，降低有用性；需要在安全和有用之间做 trade-off）
  - 现在有哪些自动化越狱攻击方法？（答：GCG 等基于梯度优化的对抗后缀攻击，AutoDAN 等用 LLM 自动生成越狱 prompt）

### Q8 【进阶】RLHF 和 RLAIF 有什么区别？

- **答案要点**：
  1. RLHF：Reinforcement Learning from Human Feedback，用人类标注员做偏好排序来训练奖励模型。
  2. RLAIF：Reinforcement Learning from AI Feedback，用更强的 AI 模型（如 GPT-4）来生成偏好标注和奖励信号，替代人类标注。
  3. 优缺点对比：RLAIF 成本低、可规模化、速度快；但标注质量受限于 AI 模型自身水平，可能放大偏见。RLHF 质量高但成本贵、慢、难以大规模扩展。
  4. 实际做法：通常混合使用——核心/高难 case 用人类标注，大规模常规标注用 AI 反馈，再用人类做抽检。
- **追问点**：
  - Constitutional AI 属于 RLAIF 吗？（答：是的，Constitutional AI 让模型根据一组"宪法原则"自己批判和修正自己的回答，本质上是用 AI 反馈做对齐，不需要大量人工标注）

### Q9 【实战】RLHF 后模型通用能力下降（对齐税），你怎么处理？

- **答案要点**：
  1. 诊断：先做全面 benchmark 对比（MMLU、GSM8K、HumanEval 等），确认哪些能力下降了，下降多少。
  2. 调整训练策略：(a) 降低 RLHF 强度（减小 β/KL 系数）；(b) SFT 阶段加入更多通用知识数据；(c) DPO 数据中加入更多高质量通用回答作为 chosen。
  3. 混合训练：在 RLHF 数据中混入一部分预训练数据（重放），防止灾难性遗忘。
  4. 分阶段：先做能力增强（继续预训练/多任务 SFT），再做对齐；不要在对齐阶段指望补能力。
  5. 评估：对齐后必须同时测安全性和能力，不能只看人类偏好打分。
- **追问点**：
  - 对齐税的根本原因是什么？（答：人类偏好数据的分布和预训练数据分布差异很大，RL 优化方向偏向"让人类满意"而非"正确"，模型会牺牲一些推理深度来换取回答的讨喜）

### Q10 【进阶】Constitutional AI（CAI）的核心思想是什么？

- **答案要点**：
  1. 核心思想：不给模型人工标注的偏好数据，而是给它一组"宪法原则"（如"回答要诚实、不能伤害人"），让模型自己根据这些原则批判和修正自己的回答，从而实现对齐。
  2. 流程：(a) 模型生成初始回答；(b) 让模型根据宪法原则批判自己的回答哪里不好；(c) 让模型根据批判重写回答；(d) 用修正后的回答做偏好训练。
  3. 优势：大幅减少人工标注；对齐原则可控可解释（改宪法条文就能调整对齐方向）；Anthropic 的 Claude 系列就是基于这个思路。
- **追问点**：
  - CAI 和 RLHF 的关系？（答：CAI 是 RLAIF 的一种，用 AI 自己生成偏好标注；最终还是可以接 PPO 或 DPO 训练）
  - 宪法原则一般写什么？（答：包括诚实性、无害性、公平性、帮助性等大类，每类有具体的原则条目，如"不要生成歧视性内容"）
