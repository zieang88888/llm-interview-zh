# 04 · 微调（Fine-tuning）

> 核心考点：LoRA/QLoRA、全参微调、数据准备、灾难性遗忘、过拟合

---

### Q1 【基础】全参微调 vs LoRA 的区别？各自适用场景？

- **答案要点**：
  1. 全参微调（Full Fine-Tuning）：更新模型所有参数；效果最好，但显存占用巨大（7B 模型需要 ~80GB 显存），训练慢。
  2. LoRA（Low-Rank Adaptation）：冻结原始模型参数，只在注意力层注入低秩分解的小矩阵 A 和 B（W' = W + BA）；可训练参数通常 < 1%，显存大幅降低，训练快。
  3. 适用场景：(a) 全参微调——数据量大（>10万条）、追求极致效果、有充足算力；(b) LoRA——数据量中等（几千~几万条）、算力有限、需要快速迭代、多任务多 LoRA 切换。
  4. 推理时 LoRA 可以合并回原权重（W + BA），不增加推理延迟。
- **追问点**：
  - LoRA 为什么有效？（答：微调时权重的变化量是低秩的——虽然模型很大，但适应新任务时实际改变的"方向"很少，用低秩矩阵就能拟合这个变化）
  - LoRA 一般加在哪些层？（答：默认加在注意力的 Q/V 投影矩阵；也可以加在 K/O/MLP 层；加的层越多效果越好但参数也越多）

---

### Q2 【基础】LoRA 的原理是什么？为什么低秩分解有效？

- **答案要点**：
  1. 原始权重矩阵 W ∈ R^{d×k}，冻结不动。
  2. 注入低秩矩阵：W' = W + ΔW，其中 ΔW = B·A，A ∈ R^{r×k}，B ∈ R^{d×r}，r << min(d,k)（如 r=8 或 16）。
  3. 可训练参数量：d×r + r×k，相比原始 d×k 减少了 (r/min(d,k)) 倍；比如 d=k=4096, r=8，参数量从 16M 降到 65K。
  4. 低秩有效的原因：研究表明大模型微调时权重更新的"内在秩"很低——适应新任务只需要改变少数几个方向，低秩分解足以捕获。
  5. 缩放因子 α：实际 ΔW = (α/r) · BA，α 控制 LoRA 分支的贡献强度，常用 α = 2r。
- **追问点**：
  - 训练完 LoRA 后怎么部署？（答：推理时可以把 BA 合并进 W：W_merged = W + (α/r)·BA，和原模型结构完全一致，无额外延迟）
  - LoRA 的 r 越大越好吗？（答：不是，r 太大会过拟合、训练变慢；常用 r=8~64；r=8 已经能覆盖大部分任务）

### Q3 【进阶】QLoRA 的核心创新是什么？

- **答案要点**：
  1. QLoRA = 4-bit 量化基座模型 + LoRA 微调。基座模型用 4-bit NormalFloat 量化冻结，只训练 LoRA 的 FP16 参数。
  2. 核心技术：(a) 4-bit NormalFloat 量化：一种新的量化数据类型，比 INT4 更稳定；(b) Double Quantization：对量化常数本身再做一次量化，省显存；(c) Paged Optimizers：用 NVIDIA 统一内存处理显存峰值。
  3. 效果：在单张 48GB 显卡上微调 65B 模型，效果和全参微调 FP16 差不多；大幅降低微调门槛。
  4. 局限：4-bit 基座有轻微精度损失；训练速度比 FP16 LoRA 慢（反量化开销）。
- **追问点**：
  - QLoRA 和普通 LoRA 区别？（答：普通 LoRA 基座是 FP16，QLoRA 基座是 4-bit 量化的；QLoRA 显存占用约为普通 LoRA 的 1/3）
  - 为什么 QLoRA 效果几乎不损失？（答：因为梯度只在 LoRA 的 FP16 参数上流动，基座量化只是前向传播时的近似，反向传播不受影响）

### Q4 【进阶】微调数据集怎么构建？需要注意什么？

- **答案要点**：
  1. 数据质量 > 数量：1000 条高质量数据 >> 10000 条噪声数据；标注要准确、风格一致。
  2. 数据多样性：覆盖目标场景的各种 case，包括边界 case 和少量"反例"；避免数据分布过于单一。
  3. 数据格式：严格统一（如 chat template：system/user/assistant 三段）；和推理时格式完全一致。
  4. 数据清洗：去重、去 PII、去低质量样本；检查长度分布，去掉过长/过短的异常样本。
  5. 比例：如果是在通用模型上做领域微调，混入 5%~10% 通用对话数据，防止灾难性遗忘。
- **追问点**：
  - 指令微调数据格式为什么重要？（答：模型学的就是这个格式；如果训练时用一种格式、推理时用另一种，模型表现会大幅下降；所以一定要用和推理时一致的 chat template）
  - 怎么造微调数据？（答：人工标注、用更强的模型蒸馏（GPT-4 生成）、从业务日志中清洗构造）

### Q5 【进阶】什么是灾难性遗忘？怎么缓解？

- **答案要点**：
  1. 定义：微调后模型在新任务上变好，但在原有通用能力上大幅下降；本质是微调数据分布和预训练分布差异大，模型参数被"拉"向新分布。
  2. 缓解方法：
     - (a) 降低学习率、减少训练 epoch，不要训太多轮。
     - (b) 混入通用数据（replay）：在微调数据中加 5%~20% 通用对话/知识数据。
     - (c) 用 LoRA/QLoRA：冻结基座参数，只训练小矩阵，天然缓解遗忘。
     - (d) 正则化：EWC 等方法惩罚对重要参数的改动。
  3. 验证：微调后跑通用 benchmark（MMLU、C-Eval 等）对比基线，确认通用能力没掉太多。
- **追问点**：
  - LoRA 为什么能缓解遗忘？（答：因为基座模型权重完全冻结，只是加了一个小的增量分支；原模型能力完整保留，推理时甚至可以不加载 LoRA 回到原模型）

### Q6 【实战】微调时 loss 不降怎么办？排查思路？

- **答案要点**：
  1. 先看是不是正常情况：刚开始 loss 不降可能是 warmup 阶段；确认 learning rate 是否合理。
  2. 数据问题：检查数据格式是否正确（chat template 对不对）；label mask 是否正确（只对 response 部分算 loss）；数据有没有乱码。
  3. 超参数：学习率太大→loss 震荡或爆炸；学习率太小→loss 下降慢；batch size 太小→训练不稳定。
  4. 代码 bug：检查梯度是否正常流动（LoRA 参数 requires_grad 是否 True）；检查 loss 是否正确平均。
  5. 资源问题：显存不足导致 gradient checkpointing 问题；数据加载慢导致 GPU 空转。
- **追问点**：
  - loss 爆炸了怎么办？（答：降低学习率、加 gradient clipping、检查数据里有没有异常长样本、确认 weight initialization）
  - 怎么判断 loss 是否收敛正常？（答：SFT 初始 loss 一般在 2~3 左右，收敛后降到 0.5~1.5 视任务而定；比初始 loss 降一半以上基本正常）

### Q7 【实战】怎么判断微调是否过拟合？

- **答案要点**：
  1. 画 loss 曲线：训练 loss 持续下降，但验证 loss 先降后升——就是过拟合。
  2. 具体表现：训练集上 loss 很低，但实际生成效果差、复读、格式僵化；换个问法就不会答了。
  3. 缓解：(a) 减少 epoch（一般 SFT 1~3 轮就够）；(b) 降低学习率；(c) 加 dropout / weight decay；(d) 增加训练数据量和多样性。
  4. 早停：监控验证集 loss，开始回升就停。
- **追问点**：
  - SFT 一般训几轮？（答：1~3 轮最常见；太多轮容易过拟合、风格固化；数据质量高时 1 轮就够了）

### Q8 【进阶】LoRA 的 rank (r) 和 alpha 怎么设置？

- **答案要点**：
  1. r（秩）：控制 LoRA 分支的表达能力；r 越大参数越多、容量越大，但也越容易过拟合。常用值：r=8（轻量任务）、r=16~32（中等任务）、r=64~128（复杂任务/大模型）。
  2. α（缩放系数）：实际缩放是 α/r；常用设置是 α = 2r，这样实际有效缩放 = 2。
  3. 经验法则：小任务（分类、风格迁移）用 r=8 就够；复杂任务（领域对话、多技能融合）用 r=32~64。
  4. 选 r 的思路：先从 r=16 开始试，效果不够再加；r 加倍带来的边际收益递减，但显存和训练时间线性增加。
- **追问点**：
  - LoRA 加在哪些层效果最好？（答：一般 Q/V 投影最关键；追求效果可以加到所有线性层（Q/K/V/O + gate/up/down）；追求速度只加 Q/V）

### Q9 【实战】如果只有 1000 条数据，你会怎么微调？

- **答案要点**：
  1. 数据层面：1000 条数据量不大，优先保证质量；做数据增强（同义改写、换表达方式）扩充到 3~5 千条。
  2. 方法选择：用 LoRA 而不是全参微调，防止过拟合；r 选小一点（8~16）。
  3. 超参数：低学习率（1e-5 ~ 2e-5）、少 epoch（1~2 轮）、加 weight decay 防过拟合。
  4. 正则：混入 10%~20% 通用数据，防止灾难性遗忘。
  5. 评估：小数据集一定要留验证集，密切监控过拟合。
  6. 替代方案：如果数据实在太少，考虑 few-shot prompt + RAG 方案，不一定非要微调。
- **追问点**：
  - 多少条数据才值得微调？（答：一般建议至少 500~1000 条高质量数据；少于这个数优先调 prompt 和 RAG，微调收益有限）

### Q10 【进阶】全参微调时，学习率怎么选？为什么比预训练小？

- **答案要点**：
  1. 预训练学习率：1e-4 ~ 5e-4（如 AdamW，峰值学习率）。
  2. 全参 SFT 学习率：1e-5 ~ 5e-5，比预训练小一个数量级。
  3. 为什么小：(a) 预训练是从头学知识，需要大学习率快速探索；(b) SFT 是在已有强模型上做小调整，学习率太大会破坏预训练学到的知识（灾难性遗忘）；(c) SFT 数据量小，大学习率容易过拟合。
  4. LoRA 学习率：比全参微调大，一般 1e-4 ~ 3e-4；因为只训练小矩阵，参数少需要更大学习率来有效更新。
- **追问点**：
  - 学习率 schedule 怎么设计？（答：warmup 前 3% 线性升到峰值，然后 cosine 衰减到接近 0；SFT warmup 比例可以小一些）

### Q11 【实战】指令微调数据格式为什么重要？举个例子说明。

- **答案要点**：
  1. 为什么重要：微调本质上是让模型学会在特定格式下生成特定分布的回答；如果训练和推理格式不一致，模型会"困惑"，表现大幅下降。
  2. 正确示例（LLaMA-3 格式）：
     ```
     <|begin_of_text|><|start_header_id|>system<|end_header_id|>
     你是一个 helpful assistant.<|eot_id|><|start_header_id|>user<|end_header_id|>
     今天天气怎么样？<|eot_id|><|start_header_id|>assistant<|end_header_id|>
     今天晴，20~25度。<|eot_id|>
     ```
  3. 常见错误：(a) 训练时用 A 模板，推理时用 B 模板；(b) 标签 mask 错误——把 prompt 部分也算了 loss，导致模型学怎么写 prompt 而不是写回答；(c) 缺少结束符（eos），模型不会停。
  4. 经验：一定要用模型官方推荐的 chat template，不要自己发明格式。
- **追问点**：
  - 为什么 label mask 只算 response 部分？（答：因为 prompt 部分是用户输入，我们不希望模型学习"怎么生成用户的问题"；只让模型学习"给定问题，怎么生成回答"）
